# CycleApex v3 规划：维度折线化 + 全链路灾备

> 状态：**P0 已实施（2026-11-02），P1–P3 待做**。本文所有数字来自本仓库实测，不是估计。
> P0 交付：`fetch_data.write_dim_history()` + `scripts/backfill_dim_history.py` + `pages.yml` 清单循环与断言 + `status.json.dim_rows`。前端未改动，页面表现与之前完全一致。

## 0. 结论先行

| 项 | 决定 |
|---|---|
| 图表分工 | **7 张维度卡的表盘全部退场，换成折线；表盘只剩 hero 里一个综合分**。项目名是"仪表盘"，需要一个仪式感锚点，一个就够 |
| 折线实现 | **手写 SVG，不上 ECharts**。7 个 ECharts gauge → 0 个，首屏 ECharts 实例从 10 降到 4，反而更快 |
| 数据来源 | 新增 `data/dim_history.json`（**派生文件**，可从 `history/*.json` 随时重建） |
| X 轴 | **只有一种日期：数据截止日 `as_of`**。跑批日、生成时间一律不得上轴 |
| 周末刷新 | 数据层不新增行；前端显示"周五收盘"且不画周六的点。**不是"展示周五的数据"这么简单——是不能凭空多出一个点** |
| 最大的现有漏洞 | **`stale` 状态是跑批那一刻算好写死在 JSON 里的**。Actions 停跑 5 天，页面照样显示"最近交易日收盘"，橙色告警永远不会亮 |
| 实施节奏 | P0 数据打底（前端零改动）→ P1 折线 → P2 灾备与自检 → P3 可选增强。P0 先上线观察 3 个交易日 |

- 美股从 **+0.60 滑到 +0.07**，表盘上看不出在掉。

## 2. 视觉层改造

### 2.1 新分工

| 元素 | 现在 | 改成 |
|---|---|---|
| hero 左栏 | 大字徽章 + 文字「综合分 −0.079 · 距判定线 0.25」 | 大字徽章 + **紧凑表盘 96×96**（detail 显示整数分），"距判定线"移进 `title` |
| 7 张维度卡 | ECharts gauge 118px | **SVG 折线 56px**（含阈值带）+ 末点日期 |
| 维度卡 facts | 已在 | **保留不动**（这是上一轮刚补的，别又删回去） |
| 子指标散点 | 分条图 | 保留不动 |

hero 表盘放在 `hero-verdict` 内部横向排列（表盘在左、徽章竖排文字在右），高度仍由徽章控制 ≈100px，**hero 高度不增加**。

### 2.2 折线规格（逐条可验收）

| 项 | 规格 | 理由 |
|---|---|---|
| 尺寸 | 宽 100%，高 **56px**（其中绘图区 48px，上下留 4px） | 比 118px 省 62px/张 |
| **y 域** | **固定 [−1, +1]，绝不按数据自适应** | 7 张卡要横向可比。自适应会让"债券 −0.6↔−0.5"和"情绪 +0.3↔−0.2"看起来一样陡，等于骗人 |
| 阈值带 | −0.33~+0.33 灰带 `rgba(139,148,158,.07)`，边界虚线 `1px dashed` | 让"这个点在带内=判定不变"一眼可见 |
| 零轴 | 实线 `rgba(139,148,158,.25)`，1px | 正负分界 |
| 折线 | 2px，颜色 = **当前 verdict 色**（红/黄/绿）；面积填充 6% 同色 | 颜色只描述"现在"，历史用位置描述 |
| 末点 | r=3.5 实心圆 + 1px 描边 | 唯一的"当前"锚点 |
| 末点为休市数据 | 末点改**空心**（fill=背景色） | 视觉上区分"这是收盘价"和"这是还在动的价格" |
| 首尾日期 | 11px muted，左端 `10-02`、右端 `10-30`，中间不标 | 卡宽 300px，标满必重叠 |
| 数据窗口 | 最近 **60 个数据点**（≈3 个月） | 再长则单点 <5px，看不出转折 |
| 断点 | 折线**断开不连线**（遇 `null` 或口径变更标记） | 见 §3.5，绝不假装连续 |
| hover | 共享 tooltip（一个绝对定位 div），显示 `日期 / 分数 / 判定 / 是否休市数据` | SVG `<title>` 有 700ms 延迟，体验差 |
| 降级 | 无历史数据 → 只渲染 facts、不渲染折线，不占位不留白 | 折线是增强项，不能变成新的单点故障 |

### 2.3 为什么用 SVG 而不是 ECharts

- 7 个 gauge 各自的 `echarts.init()` + `setOption` 是首屏最重的一段（实测 50–70ms）。改成 SVG 后首屏 ECharts 实例从 **10 → 4**。
- 折线只需要 `path` 一条 + 两个 `rect` + 几个 `text`，总共 <30 个 DOM 节点，比一个 canvas 实例轻两个数量级。
- 可直接吃 CSS 变量（`var(--bull)` / `var(--bear)`），不用在 JS 里重复维护色表。
- 不必维护 `GAUGE_INSTANCES` 那套 dispose/resize 生命周期。唯一的 resize 处理用 `ResizeObserver` 重画即可（纯函数，重画成本近零）。

### 2.4 高度预算（如实标注代价）

| 方案 | 单卡高度 | 第二排顶边 | 首屏效果 |
|---|---|---|---|
| 现在 | 254px | 720px | 第二排完全看不到 |
| A：折线 56 + facts 全留 | **192px** | 658px | 第二排露出 88px（标题 + 折线），数字要看滚一屏 |
| B：折线 56 + facts 全留 + 折线贴着标题 | 192px | 658px | 同上 |

结论：**采纳 A，不做 B 那种再砍 facts 的激进方案**——facts 是上一轮刚补的，砍掉是倒退。真正的收益是"7 个维度全部有趋势"，不是"一屏塞下 7 张卡"。第二排露出标题和折线，已经能看到"哪几个在拐头"，比现在一张都看不到强。

若后续仍嫌高，**唯一正确的下一步是把 facts 的两行标的压成一行 + 其余进 tooltip**（省 20px），而不是继续压折线高度——48px 以下折线就读不出形状了。

### 2.5 验收口径

- hero 高度 ≤ 280px（现在 266，加表盘后不得突破 280）
- 单卡高度 ≤ 200px
- 7 张卡全部渲染出折线，且每张有左右两个日期标注
- 1400 / 1024 / 900 / 420 四个断点下折线不溢出、日期不重叠
- Node 桩断言：`document.querySelectorAll('.dim-line').length === 7`

## 3. 数据层：`data/dim_history.json`

### 3.1 为什么必须新增一个文件

被否掉的三个替代方案：

| 方案 | 为什么不行 |
|---|---|
| 前端读 `data/history/*.json` | 365 个文件、365 次请求；且 `pages.yml` 现在明确排除 `history/`（会发布 24MB） |
| 塞进 `market.json` | 会随跑批反复增长，且 `market.json` 是第一优先级的首屏文件，不能因为一张折线变重 |
| 前端读 `series.json` | 那里是 OHLC 原始 K 线，要前端自己重算 7 个维度分，等于把服务端逻辑复制一遍 |

### 3.2 结构（紧凑格式，不为可读性买单）

```json
{
  "schema": 2,
  "generated_at": "2026-11-02T02:12:00Z",
  "as_of": "2026-11-02",
  "dims": ["us_stocks", "cn_stocks", "kr_stocks", "bonds", "gold", "sentiment", "yen_carry"],
  "calibers": { "bonds": 2 },
  "breaks": [ ["2026-10-31", "bonds", "口径由「收益率水平方向」改为「20 日变化量」"] ],
  "rows": [
    ["2026-10-30", 0.134, -0.657, -0.173, -0.050, -0.579, 0.000, -0.029],
    ["2026-10-31", 0.068, -0.696, -0.172,  1.000, -0.646, -0.240, -0.016]
  ]
}
```

- 列顺序由 `dims` 决定，行内只存数字，**单行 ≈ 55 字节**。
- 分数保留 3 位（与 `market.json` 一致）；缺失写 `null`。
- `breaks` 是**显式断点表**，前端据此断开折线并画一条竖虚线。

### 3.3 写入规则

| 规则 | 说明 |
|---|---|
| 主键 = `as_of` | **不是跑批日期**。周末跑批拿到的还是周五数据 → 覆盖周五那一行，不新增行 |
| 幂等 | 先读旧文件 → 按 `as_of` upsert → 排序 → 截断 → 写回。重复跑多少次结果都一样 |
| 保留 | 最近 **250 行**（≈1 年交易日）。超过 250 行删最旧 |
| 失败不影响主流程 | 整段包在 `try/except` 里，与 `history` 归档同等对待；写不出来只打 `[WARN]`，`market.json` 照常发布 |
| 只写"被采纳"的那份 | 与 `market.json` 同一道 `should_keep_previous` 判定：若本次跑批被拒（覆盖度更低），**dim_history 也不许写**，否则折线会出现一个页面上根本不存在的点 |

### 3.4 回填

`scripts/backfill_dim_history.py`：读 `data/history/*.json`，抽出 7 个维度分 + `as_of`（早期快照没有 `as_of`，退回 `generated_at[:10]`），按 §3.2 写出。

一次性执行，之后由 `fetch_data.py` 增量维护。**这个脚本同时是灾备的恢复手段**：`dim_history.json` 丢了、坏了、被误删，跑一次就重建，RPO ≈ 0。

### 3.5 ⚠️ 口径断点：债券 2026-10-30

实测数据：

```
2026-10-29  bonds = -0.068
2026-10-30  bonds = +1.000   ← 同一维度，一夜之间从看空到满仓看多
```

**这不是行情，是公式换了**（`build_series(invert=True)` 测收益率水平 → `bond_change_score()` 测 20 日变化量，详见 README）。

不处理的话，折线上会出现一道近乎垂直的墙，读者只会得出一个结论："债券突然极度看多"。所以：

1. `CALIBER_CHANGES` 给每个维度记一个切换边界，债券 = 2；
2. `dim_breaks()` 从行数据**反推**第一条口径变化的行，写进 `breaks`（不单独存储状态，因此不会与行数据漂移）；
3. 前端在断点处**断线 + 竖虚线 + tooltip 说明**。

> **断点落在 10-30 而不是代码上线日 10-31**：10-31 是周六，那次跑批拿到的仍是 10-30 的数据、却已用新公式重算，所以"第一条新口径记录"是 10-30。回填时同一 `as_of` 出现两份快照（10-30 跑的 −0.050 与 10-31 跑的 +1.000），按"对某交易日最新的计算"取后者。这一条已按此实现并验证。

### 3.6 ⚠️ 假期冻结段：国庆 10-02 ~ 10-08

实测：**10-02 / 10-03 / 10-07 / 10-08 四份快照的 A股 维度分数完全相同（−0.435）**，而同期美股在正常变动。这说明休市期间 A 股维度是被冻结的（K 线没更新，指标算出来当然一样）。

折线怎么画：

- 这四天**保留行**（日期确实存在），但同一数值重复四次会画出一段水平线——**这是真相**，A 股那几天确实没有新信息，不该抹掉；
- 但要在 tooltip 里标 `休市·沿用 10-01 数据`，避免被读成"横盘七天"；
- 判断依据用每行的 `stale_carry` 标记（生成时对比上一行：若该维度分数与上一行完全相同 **且** 该市场当日无新 K 线，置 `true`）。

补充：10-07 黄金从 −0.332 跳到 −0.613（单日 −0.28），10-06 A股 又从 −0.435 回到 −0.061。这两处**原因未确认**，需要在 P0 阶段用原始 K 线复核。在查清之前不要写进文档当结论。

### 3.7 体积预算

| 项 | 估算 |
|---|---|
| 250 行 × 7 维紧凑格式 | ≈ 18 KB（gzip ≈ 4 KB） |
| 相比现在的 `market.json` 7.5KB | 首屏总增量 +18KB，可接受 |
| 加载时机 | 与 `market.json` **并行** fetch，不串行等待 |

### 3.8 与 `history/*.json` 的职责边界

```
data/history/YYYY-MM-DD.json   ← 源（append-only，完整 payload，出问题时的唯一真相）
data/dim_history.json          ← 派生（窄表，只服务折线渲染，随时可重建）
```

**规则：任何时候 `dim_history.json` 与 `history/` 冲突，以 `history/` 为准，重跑回填脚本。** 这条要写进 README，否则下次有人会去手改 `dim_history.json`。

## 4. 时间轴：三种「日期」绝不能混

### 4.1 定义

| 字段 | 含义 | 能不能上 X 轴 |
|---|---|---|
| `generated_at` | 脚本什么时候跑的 | **不能**。周末天天跑，画出来就是一堆假点 |
| `data_freshness.as_of` | 数据截止到哪天（各市场取最大值） | **唯一可用的 X 轴** |
| 各维度 `facts.date` | 该维度自己最后一根 K 线的日期 | 卡片右上角小字 / tooltip |

`series_facts()` 已经在输出 `date` 字段，前端零成本可用。

### 4.2 周末刷新 = 展示周五数据（拆成三层说清）

| 层 | 做什么 | 不做什么 |
|---|---|---|
| 服务端 | `as_of` = 周五；`status = market_closed`；`note_short = "周末休市"`；`dim_history` 用 `as_of` 覆盖周五那一行 | 不按 `generated_at` 追加行；不生成"周六"的点 |
| 数据文件 | `market.json` 的 `generated_at` 变成周六，`as_of` 仍是周五 | 两者不能互相顶替 |
| 前端 | 页头「数据截止：2026-10-30（周五）· 1 天前」+ 黄标「周末休市」；折线右端日期 = `10-30`；末点空心 | 不在 X 轴右端补一个"今天"的空点；不把"生成时间"显示成"数据时间" |

现有实现已经把这三层分开了（`dataAsOf` 用 `as_of`、`updated` 用 `generated_at`），**v3 要做的是让折线也遵守同一条规则**——这是最容易出错的地方，因为 ECharts/SVG 默认按数组下标排 X 轴，一不留神 `generated_at` 就混进去了。

### 4.3 长假：现有启发式已经够用，别加节假日表

逐场景推演（`as_of` 取各市场最大日期，这一点是关键）：

| # | 场景 | `as_of` 由谁定 | `missing_td` | 现有 status | 对不对 |
|---|---|---|---|---|---|
| 1 | 普通周末 | 周五 | 0 | `market_closed` | ✓ |
| 2 | 周一盘前跑 | 上周五 | 1 | `live` | ✓ |
| 3 | 国庆（A股停 7 天，美股照跑） | 美股前一交易日 | 0~1 | `live` + `skew 5~7` | ✓ |
| 4 | 春节（同上） | 美股 | 0~1 | `live` + `skew` | ✓ |
| 5 | 感恩节/圣诞（美股停，A股照跑） | A股当日 | 0~1 | `live` + `skew 1~2` | ✓ |
| 6 | 元旦（两地同停 1 天） | 上年最后交易日 | 1~2 | `live`/`market_closed` | ✓ |
| 7 | 圣诞+元旦+周末连休 | A股 | 2~3 | `market_closed` | ✓ |
| 8 | **Actions 停跑 5 天** | **没人重算** | **JSON 里写死的是 5 天前的 0** | `live` | **✗ 漏洞** |

场景 3~7 之所以全部正确，是因为 `as_of = max(各市场)`：只要有一个市场开着，`missing_td` 就不会涨。**唯一能触发 `stale` 的情形是"所有市场同时缺 ≥4 个工作日"，而这几乎只可能是真故障。** 所以结论是：**不维护中美节假日表**（现有代码注释的判断是对的），把精力花在场景 8。

文案上有一个小改进：`skew_days > 1` 时现在只报"最早的那个市场"，若同时有 A股 + 黄金 各自滞后不同天数，会被掩盖。建议改为：

```
note_short = "最近交易日收盘 · 3 个市场滞后（A股 10-28）"
```

### 4.4 ⚠️ 场景 8 的修法：前端自检

`data_freshness` 是**跑批那一刻的快照**，写死在 JSON 里。跑批停了，这个字段不会变老。

修法（纯前端，10 行）：`renderMeta()` 里用浏览器当前 UTC 日期重算一次 `missing_td`，与 payload 里的取**更差**的那个：

```js
// payload 说 live、但按今天的日期算已经缺 4 个交易日 → 以更差的为准
const live = recomputeFreshness(asOf);        // 用同一套「缺失工作日数」算法
const st = worseOf(f.status, live.status);    // stale > market_closed > live
if (st !== f.status) { 徽章切 stale；文案 = "页面数据已停更 N 个交易日（未经服务端确认）" }
```

注意三点：
- 用 UTC 日期算，不碰本地时区（`as_of` 是 UTC 日期）；
- 误差容忍 1 天（跨零点跑批）；
- 文案必须写"未经服务端确认"——这是浏览器单方面推断，不能冒充服务端判断。

**这是 v3 里性价比最高的一项**：不增加任何数据文件，却把"整站静默停更"这个最危险的故障变成了可见的橙色徽章。

## 5. 灾备

### 5.1 故障清单

| 编号 | 故障 | 检测手段 | 自动响应 | 页面表现 | 恢复动作 |
|---|---|---|---|---|---|
| F1 | 单一数据源 404/429/断连 | `bars_ok()` <20 根 → `usable=False` | 该维度不出（`add_dim` 跳过），权重按可用维度归一化 | 该卡消失；`dimsInfo` 显示 6/7，`title` 说明缺哪个 | 下次跑批自愈 |
| F2 | 多源同时抖动 | `payload_coverage()` 下降 | `should_keep_previous()` 拒绝覆盖，`write_skipped=true` | 页面沿用上一份，无变化 | 次日跑批 |
| F3 | 全源失效 | `len(present) < 2` | `sys.exit(2)`，不写任何文件 | 线上不变 | 人工核查 + 手动 dispatch |
| F4 | 脚本抛异常 | Actions 红灯 | 不提交、不部署 | 线上不变 | 修代码 → rerun |
| F5 | Actions 超时/取消 | job 结束态 | — | 线上不变 | 手动 rerun |
| F6 | Pages 部署失败 | deploy job 红 | — | 线上不变（旧版仍在） | `gh workflow run pages.yml` |
| F7 | `GITHUB_TOKEN` 不触发 pages | `gh run list` 无 `workflow_dispatch` 来源 | `update.yml` 末尾显式触发（已内置） | — | 已修 |
| F8 | **Actions 整体停摆**（60 天不活跃被禁用、额度耗尽、仓库改名） | **前端自检（§4.4）** | 无 | 徽章变橙「已停更 N 个交易日」 | 手动 dispatch / WorkBuddy 本地跑一次 push |
| F9 | **数据错但 status=ok**（口径漂移、脏值、某维永远同号） | 健康断言（§5.3） | 写入 `status.json.checks` | 暂不阻断，靠告警 | 人工判断 |
| F10 | `dim_history.json` 丢失/损坏 | 前端 fetch 失败 | 折线降级隐藏，facts 照常 | 卡片只有数字没有线 | `backfill_dim_history.py` 重建 |
| F11 | 仓库/分支误删 | GitHub 通知 | — | 404 | 本地 clone 重建 + 打开 Pages |

### 5.2 三道已有护栏，保留不动

1. **类型铁律**：缺失 = `None`，中性 = `0.0`。`add_dim` 遇 `None` 整维不出，绝不用 0 分充当"中性"稀释。
2. **同日重跑护栏**：`payload_coverage` + `should_keep_previous`。**v3 必须把 `dim_history` 也纳入这道护栏**，否则会出现"页面拒绝了这个点、折线却记下了它"的分裂。
3. **失败守卫**：`< 2` 维非零退出。阈值偏松（历史上有过 3/13 维仍 `status=ok` 的案例），P2 阶段考虑提高到 `< 4`（7 维口径下剩 3 维已无判定意义）。

### 5.3 健康断言（P2 新增，写进 `status.json.checks`）

都是廉价的纯算术，跑在 `main()` 末尾，只报不拦：

| 断言 | 阈值 | 抓什么 |
|---|---|---|
| `overall` 单日变动 | > 0.5 | 八成是口径或数据错。实测历史最大单日变动 0.135 |
| 单维度单日变动 | > 0.8 | 债券那种换口径的一跳 |
| `as_of` 倒退 | 新 < 旧 | 时区/脏数据/上游回滚 |
| 某维度近 20 次记录 σ < 0.02 且同号 | — | **"永远亮着"检测**：估值维当年就是这样，名义测 CAPE 实际测趋势 |
| 可用维度 < 7 | — | 已有，改为进 `checks` 而不只是 `note` |

`status.json` 最终形态：

```json
{ "status": "ok", "checks": { "ok": false, "failed": ["bonds_jump"] },
  "dims_available": 7, "write_skipped": false, ... }
```

### 5.4 告警通道

- **首选**：`update.yml` 末尾加一步，若 `python scripts/health_check.py` 返回非零 → 用 `gh issue create` 开一个 issue（自带邮件通知），标题带 `generated_at`。
- **次选**：WorkBuddy 本地自动化在工作日 09:00 做一次独立校验（拉线上 `status.json`，比对 `as_of` 与今天），与 Actions 形成互检。
- **不做**：站内弹窗、钉钉/企微 webhook（当前无凭据，且增加外部依赖）。

### 5.5 RTO / RPO

| 场景 | RPO（丢多少数据） | RTO（多久恢复） |
|---|---|---|
| 单源故障 | 0（该维度当日缺失，次日补） | 次日跑批 |
| 同日重跑抖动 | 0（护栏拒绝写入） | 立即 |
| 脚本 bug | 0（不写文件） | 修完 rerun，分钟级 |
| Actions 停摆 | **最多 N 天**（N = 停摆天数，期间无数据） | 手动 dispatch，分钟级；但**数据空洞永久存在** |
| `dim_history` 损坏 | 0（可从 `history/` 重建） | 一条命令 |
| 仓库误删 | 视备份 | 重建 Pages，小时级 |

**唯一有真实数据损失的是"Actions 停摆"**——停摆那几天的行情不会补回来（Yahoo 只给历史价，但当时的实时情绪指数取不回来）。所以 §4.4 的前端自检不是锦上添花，它是这个系统里唯一能让人**知道**自己在丢数据的机制。

## 7. 明确不做的事

| 不做 | 理由 |
|---|---|
| 中美节假日表 | §4.3 已证明 `as_of = max` 让现有启发式在 7 种休假场景全部正确；表既会过期又不解决问题 |
| 折线 y 轴自适应 | 破坏 7 张卡的可比性，是"好看但骗人"的典型 |
| 在 X 轴上补"今天"的空点 | 制造不存在的数据 |
| 用 `generated_at` 当 X 轴 | 周末/长假会画出一堆假点 |
| 把折线画成 ECharts | 7 个实例换 7 条 `path`，没有理由 |
| 平滑曲线 / 渐变填充 / 面积动画 | 分数是离散阶跃（MA 排列给 ±1），平滑会伪造连续性 |

## 8. 已知限制（写进 README，不掩饰）

1. **前 20 份历史快照是 11 维口径**（估值/广度/量能/波动率还在）。v3 只用其中 7 个仍在的维度，但这 7 个里**债券在 2026-10-31 换了口径**，因此折线在 10-31 处必然断开。历史折线"可以看形状，不能做统计检验"。
2. **A股 维度日间跳跃大**（实测单日 −0.064 → −0.435，跨度 0.37）。原因是子指标是离散阶跃（MA 排列给 ±1，非连续量）。折线会把这个特性放大到肉眼可见——**这是好事**，表盘时代它只是"指针抖了一下"。
3. **`dim_history` 与 `history` 有 18KB 的冗余存储**。接受：推导一个可缓存索引比为每次渲染重算便宜得多。
4. **前端自检会产生"伪陈旧"**：用户把系统时间调快一个月，页面会报停更。不处理（成本 > 收益），但文案写"未经服务端确认"。
5. **7 维模型没有任何领先指标**（同期量对同期量），折线改善的是**可读性**，不是**预测力**。这一点在 README 的负结果章节已经写明，v3 不改变它。
